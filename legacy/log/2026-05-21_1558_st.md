## 주요 결정

### 1. 시나리오 그룹화 기준
SRS의 UC-01~UC-06을 그대로 그룹으로 사용. 각 UC는 **기본 흐름 + 대안·예외 흐름**을 별도 테스트로 분리. 

| UC | 시나리오 수 | 커버 흐름 |
|----|-----------|---------|
| UC-01 시스템 기동 | 2 | 기본(준비완료 로그), 기본(Forward+Standard 진입) |
| UC-02 자동 청소 | 2 | 기본(다중 루프→종료), 대안(장애물 우선 — NFR-SAFETY-01) |
| UC-03 장애물 회피 | 6 | 경로 3개 + 복귀 확인 + 센서 마스킹 + 명령 순서 |
| UC-04 강화 청소 | 4 | 기본(부스트 활성) + 재감지 무시 + 장애물 후 재개 + 먼지센서 skip |
| UC-05 정상 종료 | 3 | 즉시 종료 + 청소 중 종료 + 부스트 중 종료 |
| UC-06 오류 종료 | 2 | 예외→안전 종료 + 오류 로그 확인 |

### 2. 사용자 입력 시퀀스 추상화 방식
`RVCSimHarness`의 `schedulePause()` / `scheduleCommand(UserCommand)` 사용:
- `schedulePause()`: 루프 1회 실행 보장 (명시적 `nullopt` 주입).
- `scheduleCommand(POWER_OFF)`: 정상 종료 트리거.
- 이 패턴은 `/simulator` 단계에서 정의한 `SimCommandSource`의 `sendPause()` / `sendCommand()`와 1:1 대응.

### 3. FR-MOVE-03 시스템 수준 검증 방법
단위 테스트에서는 `ObstacleHandler.avoidAndReturn()` 내부에서 front 미호출을 검증했다.
시스템 수준에서는 `resetSensorCallCounts()` 후 `run()` 실행, `frontSensorCalls() == 1` 검증 — "회피 중 front 재폴링 없음" 의미. 만약 `executeTurn()` 내부에서 front를 폴링하면 `>1`이 되므로 규칙 위반 탐지 가능.

### 4. 기존 `test_system_scenarios.cpp` 유지
Stub 직접 사용 방식의 기존 7개 시나리오는 그대로 유지 (단위 경계와 시스템 경계의 이중 커버리지). 신규 `test_uc_scenarios.cpp`는 `RVCSimHarness`를 사용하여 UC 추적 가능성을 명확히 함.

### 5. 빌드 경로 문제
프로젝트 경로의 `#5` 때문에 `cmake --build build` 재구성이 실패함. `/tmp/rvc_build` 심볼릭 링크 빌드 경로를 사용 (CLAUDE.md 4절 업데이트 완료).
