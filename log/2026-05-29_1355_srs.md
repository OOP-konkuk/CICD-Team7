# /srs

## 사용 프롬프트
`/srs` (REVIEW 항목은 권장안으로 확정)

## 주요 결정
- **legacy SRS(v1.0)를 그대로 인계 후 우측 센서 삭제가 강제하는 부분만 수정.** ID 체계·FR/NFR/UC 집합·문장 표현은 보존. 삭제·추가된 요구사항 없음 → 추적성 매트릭스 일치.
- **"센서(입력) 삭제 ≠ 우회전(모터 출력) 삭제" 구분을 SRS 본문에 명문화.** §6.2에 "삭제된 것은 우측 근접 센서이지 우회전 이동 능력이 아니다" 주를 추가. `MotorCommand` 우회전·NFR-TIMING-03의 "좌/우 회전" 표현은 일치 유지.
- **회피 경로 단순화 반영**: FR-MOVE-02 "3-경로 → 2-경로", 방향 결정 표에서 우측 열·우회전 단독 행 삭제. 후진 행은 좌측 재조회 기반으로 단순화.
- **REVIEW #2(권장안 적용)**: `executeBackAndTurn`의 후진 후 blind 우회전을 **존속**으로 확정하고, 그 의미를 결정 표 주석(※)으로 명시("우측 센서 없이 수행되는 최후 탈출"). 코드 변경 불요.
- **REVIEW #4(권장안 적용)**: `docs/specs` 3파일을 `/srs`에서 함께 갱신해 SRS와 일관성 유지. requirements.md 추적성 표 R3.4(우회전) 제거·재번호, use-cases.md UC5 매핑 제거.
- **§1.4 참고 문서(워크플로우 문구)는 우측 센서와 무관 → 미변경(일치).** 최소 수정 원칙 준수.

## 결과 요약
legacy SRS를 인계받아 오른쪽 근접 센서 삭제를 SRS와 docs/specs 3파일에 일관 반영했다. FR/NFR/UC의 ID·집합은 변동 없이(삭제·추가 0건) 내용만 단순화했고, 핵심 의미 변화(회피 경로 2-경로화, blind 우회전 존속)를 본문 주석과 변경 이력 표로 명시했다. "센서 입력 삭제 vs 우회전 출력 존속" 구분을 모든 문서에 일관 적용해 과잉 삭제를 방지했다.
