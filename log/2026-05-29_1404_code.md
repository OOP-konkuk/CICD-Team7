## 주요 결정
- **legacy `include/`·`src/`·`CMakeLists.txt`를 최상위로 그대로 인계 후 우측 센서 삭제가 강제하는 파일만 수정.** 파일 분할·클래스명·디렉토리 보존(새 파일·재명명 0건).
- **우측 센서 배선 제거 일관 적용**:
  - `CleaningEngine` ctor `IProximitySensor& rightSensor` 인자 + `right_` 멤버 제거, `obstacleHandler_(leftSensor, rightSensor, …)` → `(leftSensor, …)`.
  - `ObstacleHandler` ctor `right` 인자 + `right_` 멤버 제거.
  - `main.cpp` `DemoSensor front, left, right;` → `front, left;`, 엔진 생성 인자에서 `right` 제거.
- **회피 로직 단순화**: `selectPath()`에서 `if(!right_.isBlocked()) return TURN_RIGHT;` 제거 → "좌 비면 좌회전, 아니면 후진". `avoidAndReturn()` 스위치의 `TURN_RIGHT` 케이스 제거, `BACK_AND_TURN` 로그 "전방·좌·우 막힘"→"전방·좌 막힘". `AvoidPath::TURN_RIGHT` enum 멤버 제거.
- **REVIEW 권장안 적용 — `executeBackAndTurn()` 존속**: 좌 센서만 재조회해 좌 막힘 시 `MotorCommand::TURN_RIGHT`(blind) 발행하는 로직을 **유지**. 우측 센서 미사용이라 변경 불요. 주석만 "좌 센서 재조회 + blind 최후 탈출"로 명확화.
- **`MotorCommand::TURN_RIGHT` 존속(일치)**: 모터 구동 명령이므로 삭제하지 않음. `main.cpp`의 DemoDriveTrain `"TURN_RIGHT"` 라벨 문자열도 그대로(모터 명령 5종 배열 유지).
- **SDD↔코드 선재 불일치 처리**: SDD §3.2는 `ObstacleHandler(front, left, …)`였으나 빌드 진실인 구현 코드는 `front` 없이 `(left, …)`. `/code`는 코드 기준으로 `right`만 제거(= `(left, drive, log)`). SDD 註에 기록된 대로 처리.
- **CMakeLists.txt 일치**: `file(GLOB)` 기반이라 센서별 항목이 없어 무수정. 빌드 검증으로 확인.
