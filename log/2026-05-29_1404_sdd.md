# /sdd

## 사용 프롬프트
`/sdd`

## 주요 결정
- **legacy SDD(v1.0)를 그대로 인계 후 우측 센서 삭제가 강제하는 부분만 수정.** 계층 구조·클래스명·인터페이스명·파일 분할은 전부 보존(재설계 없음).
- **컴포넌트 시그니처 수정**: `CleaningEngine`·`ObstacleHandler` ctor에서 `IProximitySensor& right(Sensor)` 인자와 `right_` 멤버 제거. "IProximitySensor (3개)→(2개)". `ObstacleHandler` 책임 "3-경로→2-경로".
- **추상화 인터페이스는 일치**: `IProximitySensor`가 방향 비특정(`isBlocked()`)이므로 인터페이스 자체는 legacy 그대로. 우측 센서 삭제는 인스턴스 개수(3→2)에만 영향 — 일치 註 추가.
- **타입 설계**: `AvoidPath::TURN_RIGHT`(우측 센서 의존 경로) 삭제, `BACK_AND_TURN` 주석을 "전·좌 막힘"으로. `MotorCommand::TURN_RIGHT`(모터 명령)는 **존속**(주석 보강). "센서 입력 삭제 ≠ 우회전 출력 삭제" 일관 적용.
- **시퀀스 다이어그램**: §6.3(후진+재조회)에서 `RS(right)` participant·`OH->>RS:isBlocked()` 삭제, "전·좌·우 막힘→전·좌 막힘", 회전 라인을 좌측 재조회 기반으로 갱신. §6.2(좌회전)은 우측 무관이라 일치.
- **선재 불일치 플래그(중요)**: legacy SDD §3.2/§10.4의 `ObstacleHandler` ctor는 `front`를 포함하지만 legacy **코드**는 `(left, right, drive, log)`로 `front`가 없다. 이는 우측 센서와 무관한 TP#6 이전부터의 SDD↔코드 불일치 → 최소 수정 원칙에 따라 **수정하지 않고 §3.2 註로 기록만** 했다. `/code`는 빌드 진실인 코드를 기준으로 `right`만 제거.
- **빌드 명령 경로**를 `#5_Team7` → `#5_Team7_NoRight`로 교정(우측 센서와 무관하나 경로 stale이라 한 줄 갱신).

## 결과 요약
legacy SDD를 인계받아 우측 센서를 컴포넌트 시그니처(2개 ctor)·회피 시퀀스·`AvoidPath`에서 일관 제거했다. 방향 비특정 추상화·파일 매핑·`MotorCommand::TURN_RIGHT`는 일치로 명시해 최소 수정을 정량화했다. 변경 컴포넌트 2개(CleaningEngine·ObstacleHandler), 수정 시그니처 2개, 다이어그램 변경 1개(§6.3). SDD↔코드 선재 불일치(`front`)를 발견·기록해 `/code` 단계에 인계했다.
