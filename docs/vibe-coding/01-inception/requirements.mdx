# Requirements — RVC Control SW

> **Phase**: Inception  
> **Output**: Functional Requirements (FR) + Non-Functional Requirements (NFR)

---

## Functional Requirements (FR)

| Ref. # | Functional Requirement |
|--------|------------------------|
| FR-1 | RVC는 가정의 바닥을 자동으로 청소(청소 및 걸레질)한다 |
| FR-2 | 청소 중 장애물이 없으면 직진으로 이동한다 |
| FR-3 | 전방에 장애물이 감지되면 청소를 멈추고, 좌 또는 우로 방향을 전환한 뒤 청소를 재개한다 |
| FR-4 | 전방, 좌측, 우측 모두 장애물이 있으면 후진한 뒤 좌 또는 우로 방향을 전환하고 전진한다 |
| FR-5 | 먼지가 감지되면 **5분 동안** 청소 파워를 높인다 |
| FR-6 | HW 제어의 세부 설계 및 구현은 고려하지 않는다 |
| FR-7 | 자동 청소 기능에만 집중한다 |

---

## Non-Functional Requirements (NFR)

| Ref. # | Category | Non-Functional Requirement |
|--------|----------|----------------------------|
| NFR-1 | **Performance** | 전방 센서 인터럽트 발생 후 즉시(실시간) 반응해야 한다 |
| NFR-2 | **Performance** | 주기적 센서(좌/우/먼지) 입력에 대해 주기 내에 처리를 완료해야 한다 |
| NFR-3 | **Extensibility** | 센서를 추가하거나 교체할 수 있는 구조로 설계해야 한다 |
| NFR-4 | **Extensibility** | 향후 모바일 앱 연동 기능을 추가할 수 있는 구조여야 한다 |
| NFR-5 | **Maintainability** | SOLID 원칙을 준수하여 설계한다 |
| NFR-6 | **Testability** | Google Test 기반의 단위 테스트 및 시스템 테스트를 지원해야 한다 |
| NFR-7 | **Portability** | C++로 구현하며, 플랫폼 독립적인 구조를 지향한다 |
| NFR-8 | **Performance** | 파워업 청소 지속 시간은 5분(300,000ms)으로 한다 |
| NFR-9 | **Configurability** | 파워업 청소 지속 시간은 생성 시점에 주입 가능한 구조여야 한다 |

## Input / Output Event Summary

| Event | Description | Type |
|-------|-------------|------|
| Front Sensor Input | 전방 장애물 감지 | True / False, **Interrupt** |
| Left Sensor Input | 좌측 장애물 감지 | True / False, Periodic |
| Right Sensor Input | 우측 장애물 감지 | True / False, Periodic |
| Dust Sensor Input | 바닥 먼지 감지 | True / False, Periodic |
| Direction (출력) | 모터 방향 명령 | Forward / Backward / Left / Right |
| Clean (출력) | 청소기 상태 명령 | On / Off / Up |
